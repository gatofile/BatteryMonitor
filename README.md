# BatteryMonitor 1.9.2

Native Kotlin / Jetpack Compose battery dashboard for Android 10 or newer.

[Download the Android APK](https://github.com/gatofile/BatteryMonitor/releases/download/v1.9.2/BatteryMonitor-v1.9.2.apk) · [All releases](https://github.com/gatofile/BatteryMonitor/releases)

AMOLED dashboard, continuous background monitoring, charging/discharging sessions, app-usage estimates and independently customizable home-screen widgets. Everything stays on your phone. No ads, accounts, root or internet permission. Version 1.9.2 passes 156 automated tests; physical HyperOS launcher and battery-use testing remains outstanding.

## Build

Open this folder in Android Studio. Install Android SDK Platform 35 and Build Tools 35.0.0, select JDK 17 for Gradle, and sync the project. Android Studio creates `local.properties` for your SDK location. Alternatively, set `ANDROID_HOME` to your SDK directory.

On Windows, from this folder:

```powershell
.\gradlew.bat assembleDebug
```

On macOS/Linux, use `chmod +x gradlew` once, then `./gradlew assembleDebug`.

APK: `app/build/outputs/apk/debug/app-debug.apk`.

## Install

Enable USB debugging on an Android 10+ device, connect it, and authorize the computer. With Android SDK platform-tools on your PATH:

```powershell
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

You can also copy the APK to your phone, open it, and allow installation from the app you used to open it.

Screen transitions, charging, unknown screen state and gaps are excluded. Per-state current-derived percentages and measured durations are checkpointed with the session, so these rates survive process restarts. Without supported current/capacity, the early fallback requires 1% gauge change over one observed minute; established gauge averages still use five minutes and 2%. Session counters and power totals are checkpointed alongside samples. Abrupt termination can lose work since the last successful transaction.

Keep sampling with screen locked is enabled by default for background monitoring. It holds a partial CPU wake lock, with a ten-minute timeout renewed every five minutes only while the recorder is enabled. Disabling the option, stopping monitoring or destroying the service releases it. This increases battery consumption, including measured standby drain; longer intervals do not eliminate the cost of keeping the CPU awake. Android Doze can ignore wake locks unless the app is exempt. The Background reliability card shows the locked-screen sampling switch and its explanation; diagnostic text and system-settings shortcuts have been removed. Manufacturer termination is not always distinguishable from other system stops. No wake-up alarms or direct optimization-exemption permission are requested. START_STICKY and opted-in boot/app-update receivers request restoration only where Android permits. If startup is blocked, an actionable notification is posted when notifications are allowed; Settings also offers Restart. A force-stop or system user-stop can halt monitoring; open the app again to resume. Automatic restart, uninterrupted monitoring and exact sampling intervals are not guaranteed; graphs retain real gaps.
